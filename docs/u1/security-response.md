# 보안 예외와 실제 노출 대응

ND-SEC-11/NFR14.2의 로컬 구현은 `scripts/u1/security-policy.ts`다. 실제 보안 검사 `security.ts`는 명시적 `security-exceptions.json`/`secret-exposures.json`을 같은 검증기로 읽고 `.reports/u1/security-policy.json`을 보존한다. `security-policy.spec.ts`가 담당·사유·만료·재검토·잔여위험과 원래 발견/사건 ID, 명시 boolean 확인, 미해결/완료 의미를 검사한다.

현재 두 목록은 비어 있다. 실제 노출·폐기·교체 성공을 관찰한 결과를 발명하지 않는다. Trivy source secret 발견은 즉시 검사 실패다. high/critical 발견은 예외 문서로 면제하지 않는다. IaC의 특정 false positive와 승인된 공개 고객 접점/HTTPS egress의 조건부 설계 대조는 `iac-adjudication.json`에 별도로 남기며 실제 보안 예외 목록으로 옮기지 않는다. 실제 회사망/자격이 준비되지 않은 설계를 공개 활성화하는 허가는 없다.

새 실제 예외는 담당 참조, 사유, 만료, 만료 이전 재검토, 잔여위험, 원래 발견 참조를 기록한다. 문서화·재검토 필요·만료는 모두 검사 성공과 구분되며 이 프로젝트의 보안 하한을 낮추지 않는다. 현재 자동 검사에는 미해결 위험으로 실패시키며 실제 적용은 별도 명시 검토가 필요하다.

실제 비밀 노출을 관찰하면 해당 실제 credential을 즉시 폐기/회수하고 안전한 별도 경로에서 교체한다. source/image/로그/사본을 삭제했어도 기존 비밀이 유효하면 대응 완료가 아니다. 원래 노출 시각·credential 참조만 기록하며 원문 secret을 목록이나 보고서에 넣지 않는다. 실제 사용 이력, 접근 범위/업무 영향, 관련 로그와 백업/산출물·사본의 남은 노출을 각각 대조하고 각 확인 근거를 별도 접근 통제된 운영 기록에 연결한다. 복구로 폐기된 credential을 다시 유효화하지 않는다.

모든 확인 boolean이 있어도 이 로컬 정책 함수가 실제 사건·회전 성공을 증명하지 않는다. 미확인 상태는 `OBSERVED_OPEN`으로 유지하고 실제 보안 담당자/운영자와 근거를 대조한다. source 발견, 실제 노출 대응, 변경한 credential의 제공자 적용/회수 확인, 자료 보관/파기는 서로 다른 증거다. 운영 AWS/수신/법·기업 정책 미준비의 기존 gate를 유지한다.
