# 전체 합성 저장 규모와 부하 프로필

준비는 실제 두 로컬 PG에 명시적 합성 account/binding/person profile을 보호 저장하고 기업 신청→직원 확인→승인→별도 최초 관리자 지정→조직 기준→확인된 구성원→명시 거래 역할/부여의 정상 owner 절차를 사용한다. 실제 기업/사람/위임 확인을 뜻하지 않는다.100기업/1000고객/10직원과10000상품을 준비한다.

100000개 과거 저장 규모 fixture는 실제 typed 원본/전후 이력/Receipt/구매 당시 조건/품목별 미확인/필요 Fact·Work·Outbox·금지 permit를 완전 after-image로 독립 보호한다. 모든 과거 주문은 REVIEW_REQUIRED이고 필요한 Work/Outbox는 원래ID의 명시 보류다. 실제 HTTP 성공 ACK·공급/지급/발급/통지 성공으로 만들지 않는다.1%50품목/45%4품목/54%5품목으로 평균5/최대50을 정확히 구성하며 사업 상한100과 구분한다.

측정의 신규 요청은 실제 API/현재 인증·grant/owner/두 PG ACK/worker를 거친다.100개 현재 세션, 정상20req/s·30분(조회80%/변경20%), peak100req/s·5분,20req/s 회복5분·hold10분을 축소하지 않는다. 변경을 전체 현재 사용자에게 고르게 배분하며 실제 등록된 성공 활동만 idle을 갱신한다. 원래 접수 ACK는 호출자에서 독립 stream으로 관찰하고 원본·이력·필요 작업·중복/타기업/권한·외부 미확인을 별도 대조한다.

로컬 source/DB/도구·CPU/메모리·배경 작업·측정 시각과 실제 수치/실패를 기록한다. AWS Fargate/RDS 실제 성능·AZ복구·Cognito/회사망·30일 가용성을 로컬 통과로 대체하지 않는다. local mandatory 실패/미실행은 통과로 바꾸지 않는다. 같은 두 PG를 초기화하는 통합 시험은 전체 부하/복구가 끝난 뒤 실행하고, UI 단위/CDK/TLS/보안 등 독립 검사는 별도로 진행한다.
