# U1 Implementation Readiness Questions

## Scope

u1-integrated-foundation의 승인된 구현 계획을 실행하기 전에 확인할 미확정 정책과 환경을 기록한다. 계획 승인 질문 파일은 승인 당시 내용을 보존하며, 추가 질문과 답변은 이 파일에서 관리한다. 답변 전에는 해당 선행조건을 사실로 가정하거나 관련 구현을 진행하지 않는다.

## Q1. 주문 1건의 상품 항목 상한

주문 1건에 담을 수 있는 상품 항목을 최대 몇 개로 정할까요? 하드웨어 주문과 소프트웨어 주문 각각에 적용한다. 항목 수는 구매 수량과 별개다. 예를 들어 상품 A 10개와 상품 B 20개는 2항목·총수량30개다. 기존 시험 최대50품목과 목록 조회 최대100건은 주문 상품 항목 상한으로 확정된 값이 아니다.

A. 최대100개. 첫 버전의 명시적 상한 후보로 설정하고 서버 계약·UI 안내·100/101 경계와 해당 부하를 검증한다. 성능 검증 결과나 실제 고객 적합성이 확인된 숫자가 아니다.
B. 최대500개. 더 큰 일괄 주문을 허용하고500/501 경계·요청/저장/보호 원장·화면/부하를 확대 검증한다. 성능 목표 달성을 가정하지 않는다.
X. Other (please specify). 원하는 숫자 또는 하드웨어/소프트웨어별 기준을 설명한다.

[Answer]: A — 최대 100개. 하드웨어·소프트웨어 주문 각각에 적용하며 구매 수량과 별개다. 사용자 선택: 1.

한도 초과를 자동 분할·부분 접수로 처리하지 않는다. 확정한 계약/오류·정책 개정과 전체 입력 거절·안내/경계 시험에 연결한다. 새 한도 확인은 구매 수량 한도나 공급/가격/판매 수락 확인을 대신하지 않는다.

## 기존 결정으로 해소한 기업/최초 관리자 검증 준비

NFR Design Q24 A와 Q24-F1 및 WF02·BR2.1–2.3·ND-SEC-03을 그대로 적용한다. 가상 기업 A/B와 고객/직원 계정·합성 증거를 명시하고, 원본 대상/개정/확인 항목·유효/미확인/충돌 상태를 구분한다. 이름·이메일 일치만으로 동일인이나 기업 관계를 확인한 것으로 처리하지 않는다.

적용할 시험 profile은 Account/VerifiedPersonLink의 동일인 다른 계정과 미확인 연결, 초기 직원의 비공개 최소 staff.role.manage 준비, 현재 업무 권한 부여, 일반 신청과 enterprise.approve 승인, CE02 별도 최초 지정 및 organisation.manage/user.manage/role.manage 최소 grant를 포함한다. 주문 권한을 자동 부여하지 않는다. 현재 권한/개정·MFA/허용 직원 접점·원장 보호 절차와 정상/거절/미확인·회수 경합을 우회하지 않는다.

합성 provider/접속 대역은 시험 구성에만 등록한다. 실제 Cognito/회사망·기업·동일인/위임 확인 및 실거래 준비 완료로 해석하지 않는다. 운영 설정의 미등록/미확인 경로는 성공을 반환하지 않는다. 이 시험 profile은 기존 선택의 구체화이며 새 사업 정책 승인이나 시험 실행 결과가 아니다.

## Q2. 사전 복구 코드의 만료 정책

인증 앱을 분실했을 때 비밀번호와 함께 사용하도록 미리 발급·보관하는 일회용 복구 코드의 유효기간을 어떻게 정할까요? 기존 설계는 발급/보관 확인·원자 한 번 사용·재발급 시 기존 코드 전체 무효화·계정/인증 연결 세대와 회수·재등록 목적 제한을 확정했지만, 정기 만료 기간은 아직 정하지 않았다. 이 질문은 복구 코드의 수명 정책만 결정한다.

A. 정기 만료 없이 유지. 사용한 코드·재발급한 이전 코드·명시적 회수/계정 또는 인증 연결 세대가 무효화된 코드는 거절한다. 정기 교체를 놓쳤다는 이유로 비상 복구가 막히는 경우를 줄이기 위한 첫 버전 권장안이다. 유출 의심에 따른 회수/현재 권한 확인을 면제하지 않는다.
B. 발급 후 180일에 만료. 만료 안내와 재발급을 연결하고, 만료된 코드만 가지고 있는 경우 기존의 확인된 담당자 복구 절차로 연결한다. 180일은 비교를 위한 제안값이며 표준 의무값이나 기존 승인값이 아니다.
X. Other (please specify). 원하는 기간 또는 고객/직원별 정책을 설명한다.

[Answer]: A — 정기 만료 없이 유지한다. 사용한 코드, 재발급한 이전 코드, 회수된 코드와 무효화된 계정/인증 연결 세대의 코드는 거절한다. 사용자 선택: 1.

사용한 코드의 재사용·옛 발급 세대/인증 연결의 코드·계정 무효화를 두 선택 모두 거절한다. 만료 없는 코드도 재등록 목적 제한과 비밀번호 검증을 우회하지 않는다. 코드 수량/entropy/verifier·시도 제한은 공식 보안 근거와 실제 지원·공격/동시성 시험으로 별도 기술 설정을 고정하며 이 질문으로 미확정 숫자를 승인한 것으로 처리하지 않는다.
