# OMS Functional Design 질문 — 최소 통합 실행 기반

**Unit:** u1-integrated-foundation
**Mode:** Guide me

## Prior Context

- 첫 단위는 필요한 신원·MFA, 기업 승인·권한, 내부 직원의 최소 상품 등록과 고객 조회, 고객 주문 접수·지속 기록·확인 대기·원래 접수 식별자 재조회를 연결한다. 후속 단위 없이 실행하며 미구현 공급·지급·발급을 완료로 표시하지 않는다. 전체 제품 범위를 이 단위로 축소하지 않는다. [S1–S2·S8]
- 고객 기업의 이용은 신청 후 내부 직원 확인·승인을 거친다. 최초 관리자는 내부 직원이 확인·지정하고, 이후 고객사 관리자가 자기 기업의 조직·소속·역할을 관리한다. 관리자라는 이유만으로 주문 등 모든 업무 권한을 부여하지 않는다. [S3·S6]
- 부서와 사업장 두 기준, 조합·사업장 전체·부서 전체·기업 전체 범위, 행위별 허용 범위의 합집합은 이미 결정됐다. 다른 기업 접근이나 서로 다른 행위의 범위를 교차 결합하는 것은 금지한다. 이 결정을 다시 묻지 않는다. [S3·S6]
- 주문을 보호하는 기업·부서·사업장 문맥은 주문 원본에 기록하고 대금·HW·SW·후속·조회에서 동일하게 사용해야 한다. 주문자의 나중 소속에서 과거 문맥을 추측하지 않는다. 계약 명세는 조직 정책·개정과 부서/사업장 참조를 갖는 TargetScope를 정의했지만, 조직 미사용과 변경 효력의 상세 정책은 미정으로 남겼다. 아래 두 질문은 이 미정 항목만 구체화한다. [S2·S5·S7]
- 요청 식별자·중복 방지, 현재 권한 대조, 성공 접수 전 지속 커밋, 미확인과 확인 사실 구분, 구매 당시 조건 보존, PC 화면 기준과 직원 내부망/MFA 조건은 기존 결정을 유지한다. 언어·DB·인증 제품·AWS 서비스·실제 제공자를 여기서 선정하지 않는다. [S3·S5·S8]
- 기업/최초 관리자 확인의 실제 증거·계정 준비, MFA·세션·직원망, 저장/복구·국내 위치·보관과 실제 전달 수단은 기존 미결정 사항을 유지하고 관련 설계·코드·실데이터 취급 전 확인한다. 이 질문의 답변만으로 실제 고객 검증·접근권 확보·운영 목표 달성이나 주문 조직 문맥 보완 완료를 표시하지 않는다. [S2–S5·S8]

## Q1. 주문의 대상 부서·사업장은 모든 기업에서 둘 다 지정해야 하나요?

이미 정한 부서·사업장별 접근 범위를 주문 데이터에 연결하려면, 조직을 사용하지 않는 기업과 단순 입력 누락을 구분해야 한다. 예를 들어 사업장은 있지만 별도 부서 구분이 없는 고객사를 어떻게 취급할지 정한다. 한 주문에는 하나의 대상 조직 문맥을 기록하며, 주문자는 주문 제출 권한이 허용하는 대상 중에서 선택한다. 이 대상은 요청자의 현재 소속과 구별한다.

A. 기업의 실제 조직 구성에 맞춘다. 권한 있는 고객사 관리자가 부서·사업장 각각의 사용 여부를 명시하고 이력을 남긴다. 사용하는 기준의 값은 주문에 필수로 지정하며, 사용하지 않는다고 명시한 기준만 '해당 없음'으로 기록한다. 미설정·미확인·입력 누락은 해당 없음으로 처리하지 않고 주문 제출을 거절한다. 두 기준을 모두 사용하는 기업에서는 둘 다 필수다. (권장)
B. 모든 기업의 주문에 부서와 사업장을 둘 다 필수로 지정한다. 별도 조직 구분이 없는 기업도 주문 전에 실제 업무에 맞는 부서·사업장을 등록해야 하며, 임의의 가짜 조직을 자동 생성하거나 누락을 허용하지 않는다.
X. Other (please specify)

[Answer]: A. 기업의 실제 조직 구성에 맞춘다. 권한 있는 고객사 관리자가 부서·사업장 각각의 사용 여부를 명시하고 이력을 남긴다. 사용하는 기준의 값은 주문에 필수로 지정하며, 사용하지 않는다고 명시한 기준만 '해당 없음'으로 기록한다. 미설정·미확인·입력 누락은 해당 없음으로 처리하지 않고 주문 제출을 거절한다. 두 기준을 모두 사용하는 기업에서는 둘 다 필수다. 사용자 선택: "1" (기업별 조직 구성에 맞춤).

## Q2. 담당자 이동이나 조직 통폐합이 일어나면 기존 주문의 접근 대상은 어떻게 처리할까요?

예를 들어 서울·IT 주문을 제출한 사람이 부산·IT로 이동하거나 서울·IT 조직이 폐지되는 경우다. 모든 선택에서 단순 소속 변경만으로 과거 주문의 대상을 추측·덮어쓰기하지 않으며, 조회와 변경 요청 때 현재의 계정·기업 상태 및 해당 행위의 권한을 확인한다. 이미 성공 접수한 주문·구매 조건·처리 근거는 보존한다.

A. 기존 주문의 대상은 원래 기업·부서·사업장으로 유지한다. 담당자가 이동해도 기존 대상에 대한 현재 권한이 남아 있는 경우만 접근할 수 있다. 폐지된 조직도 과거 주문과 이력의 식별자로 보존하고, 권한 있는 고객사 관리자가 필요한 기존 조직 접근 범위를 명시적으로 유지·부여·회수한다. 새 조직에 권한이 생겼다는 이유로 옛 조직 주문 접근을 자동 허용하지 않으며, 신규 주문은 현재 사용 가능한 조직만 대상으로 한다. (권장)
B. 조직 통폐합 시 기존 주문의 접근 대상을 새 조직으로 이관하는 별도 절차를 제공한다. 권한 있는 고객사 관리자가 이관 대상과 전후 조직을 명시하고, 기존/새 조직의 권한 영향·근거·변경 이력을 기록한 뒤 적용한다. 원래 주문 조직의 기록·주문 식별자·구매 당시 조건은 보존하며, 담당자의 소속 변경만으로 자동 이관하지 않는다. 이 선택에는 이관 행위의 권한과 진행 중 작업·조회에 대한 적용 시점을 추가로 정하는 작업이 필요하다.
X. Other (please specify)

[Answer]: A. 기존 주문의 대상은 원래 기업·부서·사업장으로 유지한다. 담당자가 이동해도 기존 대상에 대한 현재 권한이 남아 있는 경우만 접근할 수 있다. 폐지된 조직도 과거 주문과 이력의 식별자로 보존하고, 권한 있는 고객사 관리자가 필요한 기존 조직 접근 범위를 명시적으로 유지·부여·회수한다. 새 조직에 권한이 생겼다는 이유로 옛 조직 주문 접근을 자동 허용하지 않으며, 신규 주문은 현재 사용 가능한 조직만 대상으로 한다. 사용자 선택: "1" (원래 조직 유지).

## Assumptions & Open Questions

- Q1·Q2에서 사용자는 모두 A를 선택했다. 각 B 선택지는 미선택 대안이며 요구사항으로 적용하지 않는다.
- Q1의 주문 조직 정책은 EnterpriseAccess가 소유하고 OrderAcceptance가 제출 시 적용할 정책·조직 개정과 대상 원본을 보존하는 설계 제안이다. 구체적인 논리 엔티티·관계는 답변과 작성 전 요약 확인 후 명시한다.
- Q2의 별도 조직 이관 절차(B)는 선택되지 않았다. 기존 주문의 원래 문맥과 현재 행위 권한을 사용하는 답변(A)을 따른다.
- Domain Design의 주문 조직 문맥 누락(R-01)은 이전 승인 당시 보완 상태를 유지한다. 현재 단위의 기능 명세·엔티티/규칙·원본 연결과 검토로 확인해야 하며, 질문 생성이나 답변만으로 해결 표시하지 않는다.
- 타 단위의 대금·실제 제공·갱신 상세 정책과 실제 연동/상용 근거는 해당 단위의 선행 확인 사항으로 남긴다.

## Answer Analysis

- Q1·Q2의 답변은 모두 A로 명확하며, 권장 표시가 아니라 실제 사용자 선택으로 기록했다.
- 기업별 조직 기준 사용 여부와 원래 주문 조직 문맥 보존은 서로 충돌하지 않는다. 명시적 미사용과 누락을 구별하며 기존 주문을 현재 소속으로 다시 분류하지 않는다.
- 실제 조직·계정·외부 제공자·저장/복구 증거의 미확인은 이 두 정책 결정으로 해소하지 않는다. 이전 주문 조직 문맥 보완은 산출물 작성·원본 연결·검토를 통해 확인할 항목이다.
