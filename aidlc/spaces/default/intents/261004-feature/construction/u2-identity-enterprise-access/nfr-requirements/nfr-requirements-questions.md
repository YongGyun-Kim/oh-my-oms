# U2 보안·품질 요구사항 질문

## 범위와 기존 결정

IdentityRecovery/EnterpriseAccess가 U1의 실행 호스트 안에서 준수할 보안·정확성·접수/복구 보호·현재 권한·관측·검증 조건을 구체화한다. 기존 가용성99.9%/30분 복구·성공 접수 보존·정확성8영역, 정상/집중 시험 부하·성능 목표,1인 운영·국내 저장·test-after/Standard/제품 코드80%·필수 보안 검사 기준을 변경하지 않는다. 이미 선택한 TypeScript/NestJS+Express API·standalone worker, Next 고객/직원 접점, TypeORM/PostgreSQL, Transactional Outbox+별도 큐, 독립 보호 DB·단일 AWS 계정/CDK 및 Cognito 첫 제공자/출시 후 Keycloak 전환 경계를 다시 선택하지 않는다.

질문은 이전에 확인되지 않은 담당자 초대 수락 유효기간1개다. 대화에서 선택한 Guide me 방식으로 이어서 답변을 받는다. 이미 선택한 모드를 새 사용자 응답으로 기록하거나 답변을 대신 선택하지 않는다.

## 후속 보완과 확인 범위

- [U2 기능 명세](../functional-design/functional-spec.md)·[규칙](../functional-design/rules.md)·[확인 답변](../functional-design/functional-design-questions.md)을 적용한다. 초대는 본인의 연락 경로 확인·인증·MFA와 현재 초대/기업/조직/역할·관리 권한 검증 후 수락한다. 유효기간이 길어도 거래 권한이나 MFA 조건을 대신하지 않는다.
- [기능 설계 검토 기록](../functional-design/reviews/review-01.md)의 R-01(복구 권한의 확인 당사자 인계와 원래 case/초대/challenge 결합), R-02(보류 원본의 재개/종료), R-03(기존 명시 다중 scope의 손실 없는 변환)을 미해결 보완으로 추적한다. 보안 요구/상세 설계·검증에 연결하며 이 질문 파일로 해결/위험 수용을 선언하지 않는다. 완료된 기능 설계 산출물은 변경하지 않는다.
- 초대기간은 기존 로그인/MFA challenge5분·고객/직원 유휴30/15분·절대 세션8시간·사전 복구 코드 정기 만료 없음과 다른 정책이다. 해당 기존 선택은 [U1 NFR 요구 질문](../../u1-integrated-foundation/nfr-requirements/nfr-requirements-questions.md), [U1 NFR 설계 질문](../../u1-integrated-foundation/nfr-design/nfr-design-questions.md), [U1 구현 준비 질문](../../u1-integrated-foundation/code-generation/implementation-readiness-questions.md)에 보존한다.
- 실제 확인 정책/출처·기업/사람/위임·운영 권위·회사망/실계정·전달/제공자 지원은 확인 전 사실로 가정하지 않는다. 법정 보관 기간·인증 등급·추가 AWS 계정·단말 관리 기능을 일반 지침만으로 도입하지 않는다.

## Q1. 고객 담당자 초대를 발급한 뒤 며칠 동안 수락할 수 있게 할까요?

초대 수락의 본인 확인·MFA와 현재 권한 재검증은 이미 정했다. 아직 수락하지 않은 초대를 언제 만료시키는지는 미정이다. 아래 기간은 첫 버전의 제품 정책 제안이며 표준 의무값이나 기존 승인값이 아니다. 만료된 초대는 활성화할 수 없고, 권한 있는 관리자가 현재 조건으로 새 초대를 발급해야 한다.

A. 발급 후7일. 휴일이나 담당자의 확인 지연을 감안해 수락할 시간을 주는 첫 버전 제안이다. 수락 시 현재 기업·조직·역할/관리 권한·본인/MFA 조건을 그대로 다시 확인한다. (권장)
B. 발급 후24시간. 미수락 초대를 더 짧게 유지하고, 기간을 넘기면 관리자가 새 초대를 발급한다. 본인/MFA·현재 권한 조건은 동일하다.
X. Other (please specify). 다른 기간이나 고객사별 정책이 필요하면 설명한다.

[Answer]: A. 고객 담당자 초대는 발급 후7일 동안 수락할 수 있도록 한다. 만료된 초대는 활성화할 수 없고 권한 있는 관리자가 현재 조건으로 새 초대를 발급한다. 같은 원래 초대의 메시지 재발송은 만료시각을 연장하거나 회수된 초대를 되살리지 않는다. 기한이 남아 있어도 본인의 연락 경로 확인·인증/MFA와 현재 기업·조직·역할/초대한 관리자의 권한을 재검증한다. 사용자 원문: "1".

### 공통 만료·재발송 경계와 근거

같은 원래 초대의 메시지 재발송만으로 만료시각을 연장하거나 회수된 초대를 되살리지 않는다. 새로운 초대는 현재 관리 권한·내용을 다시 확인한 별도 원본이며 과거 초대/이력을 보존한다. 초대의 기한이 남아 있어도 관리 권한 회수·관련 역할/조직 변경 등 현재 수락 조건이 충족되지 않으면 거절/재확인을 요구한다.

[상위 요구사항](../../../inception/requirements-analysis/requirements.md)의 FR1.2/FR16.1·NFR1/5/9와 [공통/기업 접근 계약](../../../inception/contract-design/contract-summary.md)의 InvitationInput/C02를 따른다. 기존 U1 NFR 설계 Q24-F1은 초대 방식/기한을 후속 설계 대상으로 남겼고, U2 기능 명세 U2-OQ02·MembershipInvitation.expiresAt에는 미확정 유한 수명이 필요하다. 특정 인증 제공자의 임시 비밀번호 기본 수명을 OMS 고객 초대 수명으로 가정하지 않는다.

## 답변의 모호성·충돌 점검

- Q1은 발급 후7일을 명시적으로 선택했다. 기존 로그인/MFA challenge·업무 세션·복구 코드의 수명과 구별하고, 같은 초대의 메시지 재발송으로 기한을 연장하지 않으므로 기존 수명/회수 정책과 충돌하지 않는다.
- 초대의 기한은 수락 가능 기간이며 업무 권한의 유효기간이나 기업 이용 승인 기간이 아니다. 본인·MFA·현재 초대/기업/조직/역할과 초대한 관리자의 권한 조건을 완화하지 않는다.
- 가용성/복구·접수 보존·정확성·성능/시험·국내 저장·1인 운영과 기술 선택은 이전에 확인한 값/경계를 그대로 적용한다. 일반 참고 지침의 예시값이나 새 법적 의무를 추가 확정하지 않는다.
- 기능 설계의 미해결 보완은 후속 보안 요구/상세 설계·실행 검증에 연결한다. 보완의 완료·위험 수용, 실제 확인 정책/자격/제공자·회사망/실계정의 확보를 이 답변에서 추론하지 않는다.
