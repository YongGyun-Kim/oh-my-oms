# U3 상품·계약·주문 기능 설계 질문

## 확정 범위와 조사 근거

미확정 업무 기준만 확인한다. 사용자 추가 지시 원문은 "질문 한번에해"이며, 앞으로 필요한 업무 질문은 한 번에 묶어 제시하고 이미 답한 질문은 다시 묻지 않는다. 고객사10곳 이내 제한 파일럿·일주문1000 계획 목표와 한국어 PC1280 이상을 유지한다. 원래12개 주 책임 스토리와 전체 AC는 보존하지만 첫 배포 적용 부분과 후속을 구분한다. 원래 Unit 전체 완료 또는 실제 용량·배포 실증으로 표시하지 않는다.

첫 배포는 직원 상품 등록, 기업에 허용된 상품·확인된 조건, 다른 사람의 근거 확인/계약 승인, HW/SW 별도 다품목 주문과 구매 당시 조건 보존, 주문 전체 직원 수락을 제공한다. 자동 확정·부분 제공·같은 주문의 혼합 지급·복잡한 조건 자동화·자동 갱신은 후속이다. 공급·대금 조건 미확인과 접근/입력 오류를 직원 확인으로 우회하지 않는다.

책임은 ProductCatalog의 상품/공통 조건, CommercialAgreement의 기업 조건/근거/승인, OrderAcceptance의 접수/스냅샷/전체 판단으로 유지한다. 실제 대금·HW 이행·SW 실제 기간·배송 시스템의 원본을 U3가 대신 소유하지 않는다. U2 체크포인트 승인은 그 작업 검증의 승인으로서, 기존 동일인/필수 출처 검증 문제·미실증 실제 연동/신뢰 근거와 운영 배포 HOLD를 없애지 않는다.

## Q1 — 첫 배포의 상품 단가 정밀도

첫 배포의 KRW 상품 단가 입력에서 원 미만 소수를 허용할 것인가? 이는 세율·세무 처리나 법적 계약 효력을 확정하는 질문이 아니며 상품 입력/구매 조건 보존의 정밀도만 정한다.

- A. 원 단위 정수만 허용: 예를 들어1000원은 입력하고1000.5원은 자동 반올림하지 않고 지원 밖 입력으로 안내한다. 소수 단가 지원은 후속이다.
- B. 소수 단가도 허용: 소수 단가를 정확히 보존하며 허용 자릿수와 합계 처리 기준을 추가로 확인한다.
- X. Other (please specify)

[Answer]: A. 원 단위 정수

## Q2 — 같은 기업·상품의 승인 조건 중첩

같은 기업·상품·조건 항목에 서로 다른 가격/지급 조건의 유효 기간이 겹칠 때, 첫 배포에서 어떻게 처리할 것인가? 공통 상품 조건을 기업 계약으로 대체하는 정상적인 우선 적용과, 같은 단계의 기업 조건끼리 충돌하는 경우를 구분한다. 여러 상품의 계약 또는 서로 다른 조건 항목이 있다는 이유만으로 거절하지 않는다.

- A. 충돌하는 조건은 적용 차단: 새 조건을 등록·검토할 수 있지만 중첩을 해소한 정확한 개정을 다시 승인하기 전에는 적용하지 않는다. 기존 유효 조건과 기존 주문 스냅샷은 임의 변경하지 않는다.
- B. 충돌 상태로 승인 보관: 중첩된 조건을 보관하고 해당 상품의 새 주문은 전체 확인 대기로 보낸다. 직원이 조건 하나를 선택한 것만으로 고객과 합의한 가격을 변경하지 않는다.
- X. Other (please specify)

[Answer]: A. 충돌하는 조건은 적용 차단

## Q3 — 주문의 품목 입력 한도

첫 배포에서 주문 한 건의 품목 입력 한도를 어떻게 정할 것인가? 일주문1000건은 계획 목표이며 주문 한 건의 품목 수 제한과 다르다. 기존 시험의50품목은 제품 한도가 아니며 실제 고객의 필요 수량은 아직 미확인이다.

- A. 최대100품목으로 시작: 첫 배포의 명시적인 입력 정책으로 제안한다. 초과 입력은 자동 분할/절삭하지 않고 안내한다. 향후 실제 사용과 검증 근거로 변경한다. 이는 실측 용량을 보장하는 값이 아니다.
- B. 최대50품목으로 시작: 시험 가정과 별도로 이번 답변에서 제품 입력 정책을 선택한다. 초과 입력은 안내하며 실측 용량 보장이나 이미 존재하는 제품 제한으로 표현하지 않는다.
- X. Other (please specify)

[Answer]: A. 최대100품목으로 시작

표시한 질문과 같은 의미로 품목 수는 주문 입력행 수이며 각 행의 주문 수량과 별개다. 일주문1000건 목표 또는 기존 시험50품목을 이 한도나 실측 용량 근거로 대신하지 않는다.

## Q4 — 첫 배포의 추가 금액 계산 범위

원 단위 단가와 정수 수량의 곱/합계를 정확히 계산하는 것 외에 세금·배송비·할인 계산을 어디까지 자동화할 것인가? 실제 세율·법적 의무를 임의 선택하지 않으며, U3의 구매 조건/동의 보존과 U4의 청구·지급 원본 책임은 유지한다.

- A. 확인된 금액 입력과 합계 검증: 단가×수량은 OMS가 계산한다. 세금 포함 여부, 추가 비용·할인의 확정 원 단위 금액과 적용 근거는 직원이 명시해 등록/확인한다. 세율/할인율/조건별 자동 산식은 후속이다. 이미 단가에 포함된 금액을 다시 더하지 않고 미확인을0원으로 추정하지 않는다. 제출 후 총액/조건 변경에는 기존 고객 동의·승인 절차를 적용한다.
- B. 규칙 기반 자동 계산도 포함: 세율·배송료·할인율/적용 순서·계산 단위·반올림을 별도로 확인하고 계산/경계 시험을 첫 배포 범위에 포함한다. 기본 산식을 임의로 만들지 않는다.
- X. Other (please specify)

[Answer]: A. 확인된 금액 입력과 합계 검증

## 답변 간 정합성과 미확인 근거

- Q1의 원 단위 정수와 Q4의 확정 원 단위 금액 입력은 일치한다. 소수 단가를 자동 반올림하거나 세율·할인율 산식을 임의로 선택하지 않는다.
- Q2의 적용 차단은 기업 계약의 정상적인 우선 적용과 구분하며, 충돌 해결 전 기존 유효 조건과 주문 스냅샷을 보존한다.
- Q3의100품목은 사용자 선택에 따른 주문 입력행 정책이며 수량·일주문 계획 목표·실측 용량과 구분한다.
- 실제 고객의 주문 구성, 세율·법적 의무, 실제 외부 연동·신뢰 근거와 운영 배포는 이 답변으로 검증된 사실이 아니다. 확인되지 않은 금액·조건은 미확인으로 유지하고 임의 확정하지 않는다.
