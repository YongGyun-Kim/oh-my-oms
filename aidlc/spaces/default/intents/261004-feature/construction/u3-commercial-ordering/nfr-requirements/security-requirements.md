# U3 보안·처리 정확성 요구사항

## 목적과 적용 범위

[확인한 기준](nfr-requirements-questions.md)의 Looks correct를 적용한다. U3는 U1 호스트 안의 상품·기업 조건·주문 판단 library다. 이 문서는 요구사항과 검증 조건을 정의하며 코드 구현·검사 통과·실제 연동·운영 배포 완료를 보고하지 않는다. 첫 배포의 전체 직원 판단·원 단위 단가/확정 추가 금액·100입력행·일괄 제공·단일 지급 종류를 유지한다. [S1–S4]

권한·승인·정확성은 첫 배포 핵심이다. 원래 대량 부하·재해 복구·무중단·30일 실증은 후속으로 보존한다. [traceability.json](traceability.json)의 OK는 적용 가능한 요구사항 정의의 연결이고 실제 검증 성공이 아니다. Deferred는 원래 전체 목표/실증 또는 후속 화면을 이 문서로 완료하지 않았다는 뜻이며, 해당 행의 첫 배포 기본 보호 의무를 면제하지 않는다.

## Threat Considerations

| STRIDE | U3의 위협 | 요구사항/검증 |
| --- | --- | --- |
| Spoofing | 고객이 직원/타 기업으로 가장, 외부 결과/확인자 위조 | NFR1.1–1.5·NFR5.6: 현재 신원/목적/출처/개정 검증, 미확인 차단 |
| Tampering | 클라이언트 가격/수량·조건/제안 개정 변경, 오래된 판단 적용 | NFR5.2–5.5: 원본 스냅샷·현재 개정/동의 결합·정확 계산 |
| Repudiation | 등록/승인/동의·적용 근거 부인, 원본 이력 덮어쓰기 | NFR4.1·NFR5.5: 행위자/대상/개정/근거·전후·결과 보존 |
| Information Disclosure | 타 기업 가격/계약·목록/이력·로그/알림 노출 | NFR1.2·NFR11.1–11.3: 대상별 조회 권한·최소 정보·실제 저장 경로 확인 |
| Denial of Service | 과도한 입력/재전송/조건 조회로 호스트 소진 | NFR5.1·NFR5.3·NFR6.1/NFR7.1:100행·현재 호스트의 유한 입력/처리 경계,무제한 동기 재시도 금지. 기술적 byte/시간 경계는 기존 호스트 계약과 함께 상세 설계에서 검증 |
| Elevation of Privilege | 동일 직원의 다른 계정 승인,예외 경로/직원 수락으로 검증 우회 | NFR1.5·NFR5.4: 다른 사람·정확 승인 개정·동의·허용 상태 검증 |

위협은 설계에서 검토할 시나리오이며 실제 공격 발생/발생률의 확인 사실이 아니다. 실제 연동 신뢰·직원망·미실증 보호 경계를 구현/배포 준비 전 검증한다.
