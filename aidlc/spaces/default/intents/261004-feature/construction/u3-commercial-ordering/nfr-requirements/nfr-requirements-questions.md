# U3 보안·품질 요구사항 확인

## 범위와 기존 답변 적용

사용자 지시 "질문 한번에해"에 따라 필요한 확인은 한 번에 묶는다. U3는 U1 실행 기반에 포함되는 library이며 이번 단계의 필수 산출물은 security-requirements.md·tech-stack-decisions.md·traceability.json이다. 별도 성능/가용성/관측 서비스나 새 배포 단위를 만들지 않는다. 이미 답한 기술·목표는 다시 선정하지 않고 근거를 이어받는다.

[U3 기능 명세](../functional-design/functional-spec.md)와 [규칙](../functional-design/rules.md)의 전체 직원 판단·원 단위 금액·100입력행·충돌 적용 차단·다른 사람 계약 승인·고객 동의·현재 조직 권한을 유지한다. TargetScope, 조건 항목별 모든 적용 개정, 값 객체의 인라인/허용 원본 매핑과 수락 전/후 변경의 C00/C05 v2 변경 명세를 보안·정확성 검증에 연결한다. v2 스키마가 이미 구현되었다고 표시하지 않는다.

## NFR 범주와 모호성 점검

| 범주 | 기존 기준 적용과 이번 단계의 구체화 |
| --- | --- |
| 보안/접근 | 모든 사람 MFA, 현재 기업·조직·행위/대상 권한, 직원 내부망/승인 PC, 다른 사람 계약 승인, 민감 정보 최소 노출. U3의 상품/계약/주문/동의/이력·원본 근거를 대상으로 검증 |
| 정확성/보존 | 원 단위 계산·포함 항목 중복 방지, 최초 조건 불변, 중복 효과 없음, 오래된 개정 충돌, 미확인/거절/0원 구분, 성공 접수와 이력/전달 사실의 연결. 실제 복구/외부 결과를 문서 연결로 대체하지 않음 |
| 규모/성능 | 10곳/일주문1000은 계획 목표,100입력행은 제품 입력 정책. 기존 조회 p95≤1초·변경 p95≤2초·기술 오류≤0.1%는 실측 성과가 아님. 대량100k/50분 검증은 후속. 짧은 시험의 동시 사용자·정확 기간/구성은 시험 설계 시 별도 근거로 정함 |
| 신뢰성/운영 | 99.9%/30분 복구·정의한 장애의 성공 접수 RPO0 목표 보존. 재해 복구·무중단·장기간 달성 실증은 보류. U3는 원본/검토/판단/실패/충돌·대조용 근거를 제공하고 실제 배포·백업·알림은 해당 소유자 책임 |
| 데이터/규정 | 계약·주문·조건·포함 로그/백업 국내 저장과 최소 정보/접근 제한 유지. 실제 법정 보관/삭제·저장 경로·연동 자격은 확인 전 사실로 선언하지 않음. 일반 지침 숫자나 인증 의무를 임의 추가하지 않음 |
| 유지보수/기술 | 기존 TypeScript·NestJS+Express API/Nest standalone worker·Next.js+React PC·TypeORM/PostgreSQL·Transactional Outbox+별도 큐·단일 AWS 계정/CDK·Cognito→Keycloak 전환 경계 재사용. 제품 코드80%·test-after/Standard·필수 보안 검사/실패 차단 유지. 1인 기술 운영 목표로 기능 자동 축소하지 않음 |

직원/고객 유휴15분/30분·최대8시간 등 공통 인증/세션 정책은 이전 확인 답변을 그대로 이어받고 U3에서 더 약하게 만들지 않는다. 기기 인증서/단말 관리·추가 AWS 계정·새 큐/DB/제공자·법정 보관 숫자를 이 단계에서 새 기능/기본값으로 만들지 않는다.

첫 배포 실행 계획이 원래 대량 부하·재해 실증의 첫 배포 해석을 대체한다. 따라서 원래 목표와 미실증/보류 상태는 보존하되 이번 단위의 설계/검토를 대량 시험 재실행으로 확대하지 않는다. NFR 세부 ID와 실제 검증/후속 책임을 구분하여 추적한다.

현재 자료에서 이번 library 단위에 필요한 추가 제품 선택은 발견되지 않았다. 실제 고객·법적 의무·외부 근거·배포 경로가 미확인인 것은 기존 보류/검증 조건이며 임의 선택으로 해소하지 않는다. 기존 U2 동일인/필수 출처 검증 문제도 해결·위험 수용으로 선언하지 않는다. 이 파일은 기존 답변 적용을 정리한 것이며 신규 질문의 답변을 만들어 기록한 것이 아니다.

## Consolidated Summary Confirmation

U3 보안·품질 요구 문서에 아래 기준을 함께 반영한다.

- 현재 기업/부서/사업장/행위 권한·직원 내부망·MFA와 다른 사람 계약 승인을 적용한다. 조회·변경·민감 근거·이력도 동일 정보 권한으로 보호하고 기존 U2 미해결/실제 근거 미확인은 보존한다.
- 단가/비용/할인의 정확한 원 단위 계산과 중복 반영 방지,100입력행·원래 구매 조건·상품/조건별 모든 합의 개정·고정 TargetScope·정확한 제안 동의·개정 충돌·동일 요청 효과 한 번을 검증 기준으로 연결한다.
- C00/C05 v2의 복수 개정/조건 매핑 및 수락 전/후 변경 입력을 후속 구현의 필수 계약 검증 대상으로 명시한다. 현재 공유 v1이 이미 변경됐다고 표시하지 않는다.
- 기존 기술 선택·국내 저장·80% 제품 코드 커버리지·필수 보안 검사/실패 차단·1인 기술 운영 목표를 유지한다. 새로운 AWS 계정/단말 관리/보관 숫자/제공자를 임의 선정하지 않는다.
- 10곳/일주문1000·99.9%/30분 복구·RPO0 목표와 실제 측정/달성을 구분한다. 긴 부하·재해 복구·무중단·장기간 실증은 기존 후속 상태를 유지하며 새 시험을 지금 실행하지 않는다.
- 이번 단위의 산출물은 보안 요구·기존 기술 적용·NFR 추적 3개다. 성능/저장/알림의 실행 기반/운영 소유 경계를 유지하고 필요한 미실증 조건은 후속 담당과 연결한다.
