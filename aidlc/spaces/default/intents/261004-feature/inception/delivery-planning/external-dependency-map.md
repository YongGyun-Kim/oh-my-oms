# OMS 외부 의존과 준비 조건

## Scope and Reading Rules

Bolt는 하나의 구현 단위를 설계·구현하고 실행 결과로 확인하는 개발 묶음이다. 이 표는 B01–B10이 필요로 하는 실제 외부 API/데이터·계정/환경·업무 확인/승인 조건을 연결한다. 물리/업무 외부 의존과 OMS 내부 코드 구현을 구별한다. 외부 의존의 조정 책임은 해당 논리 업무 소유자에게 있으며 중앙 연동 조직/새 조정자를 만들지 않는다. SW 우리 측 실행 어댑터도 OMS 책임이고, 실제 SW 제품/발급·전달 환경의 확보 조건을 별도로 적는다. [S4–S8]

## External Dependency Map

**전체 공통 현황:** 실제 외부 업체·업무 담당자·계정/접근·자료 확보 여부와 소요 시간/완료 예정일은 모두 미확인이다. 표의 사용자·개발자는 현재 조정/기술 책임, owner 이름은 논리 책임이다. 외부 실제 담당자 배정이나 연동/사업 검증 완료를 뜻하지 않는다. 확보 소요 시간은 전 항목 **미정**이며 납기 숫자를 만들지 않는다. 기한은 이미 합의된 관련 설계/코드·구현 약속·실거래/실데이터·상용 약속 전의 조건으로 관리한다.

## Planning Blocks and Safe Continuation

- 실제 업체 명세/인증·주소·원본/최신성·안정 ID·정정/재확인·한국 저장 근거가 없으면 해당 업체 어댑터/구현 약속을 진행하지 않는다. OMS 소유 형식 계약·합성 소비 시험과 공급자 등록 준비는 그 한계를 표시해 개발한다. 관련 정책/신뢰/산식은 코드 전에 확정한다.
- 초기 대금/HW/SW 공급자가 없을 때는 미확인·준비 부족/대조로 반환하고 전체 자동 수락·출고·발급·환불 완료를 추정하지 않는다. 실제 공급자가 등록되면 관련 이전 소비자의 왕복·중복/역순·정정/권한/보존을 다시 시험한다.
- 직원 근거 등록이 승인된 대안인 업무에도 실제 원본 권위·근거/동일인·권한/수량/금액/시각을 확인한다. 외부 지연을 이유로 임의 직원 우회 권한을 만들거나 모든 API를 가짜 성공으로 바꾸지 않는다.
- 기본 신원/MFA·직원 접속/권한·지속 보존/실행 준비가 첫 동작에 필요하면 B01의 실제 시연/체크포인트가 그 조건을 기다린다. 외부 도입·실사업 확인이 없어 합성 조건으로 시연한 부분은 실제 계정/고객 검증 완료와 구별한다.
- 지연/실패는 실제 알고 있는 상태·원인·영향 경로·다음 확인·담당 역할을 기록한다. 관련 업무만 보류하고 공급/대금/회수의 원래 식별자로 결과를 대조한다. 승인된 안전 자동 재시도와 개발자 복구 시도 알림 조건을 유지한다.
- 기한/실제 담당을 확보하면 근거와 함께 이 표의 상태를 갱신하고 영향을 받는 설계/코드·데모·실거래/출시 조건을 재평가한다. 제품 범위·품질/보존 목표를 자동 축소하지 않는다.

## Assumptions & Open Questions

- A-DP3 [assumption]: 실제 신원·업무 원본/실행·통지/환경을 확보하여 승인된 OMS 경계와 한국 저장/보존·운영 요구를 충족할 수 있다. 아직 공급자 선정/접근·수요/비용·사업 인력으로 입증되지 않았다.
- OQ1–OQ10/HB-01–HB-08을 미해결 상태로 이어받는다. 확인 시점별 상세 책임은 이 표와 bolt-plan의 해당 Unit에 연결한다.
- 고객 모바일은 지원 여부 미정, 직원 모바일 제외다. ERP/WMS/PIM/CRM 전체·자동 출금/정기 결제·실제 운송·SW 실행 권한 강제 등을 미확인 외부 의존 대신 새 기능으로 만들지 않는다.
- 외부 연락/도입 계약·실데이터/실거래·운영 배포는 이 계획 작성으로 실행되거나 승인된 상태가 아니다.
