# OMS 업무 관점별 페르소나

## 정의와 근거

[요구사항](../requirements-analysis/requirements.md)과 [작성 질문 Q1](user-stories-questions.md)에서 확인한 8개 관점을 사용한다. 이는 고정 RBAC 역할·실제 직함·필요 인원 수가 아니다. 각 관점의 목표는 제품 정책에서 도출했으며, 아래 불편은 **[assumption] 검증 전 가설**이다. 실제 기술 숙련도·사용 빈도·개인 프로필은 모두 미확인으로 남긴다. [팀 개발 원칙](../practices-discovery/team-practices.md)의 1인 기술 운영 목표를 사업 업무 전체의 동일인 수행으로 해석하지 않는다.

## 관점별 정의

### P1 고객 구매 담당

- 역할·목표: 허용된 상품을 주문하고 지급·제공·갱신·후속 요청의 결과와 남은 조치를 확인한다.
- 불편 가설: [assumption] 진행·잔량·다음 조치를 알기 어려울 수 있다.
- 사용 맥락: 고객 PC 우선·모바일 웹
- 권한 경계: 고객사 권한 관리자가 부여한 행위·부서/사업장 범위만 사용
- 근거: FR4–FR5, FR11, FR13–FR14 및 작성 계획 Q1.
- 기술 숙련도·사용 빈도: 미확인. 인터뷰·실사용 관찰 전 임의 수준을 부여하지 않는다.

### P2 고객사 권한 관리자

- 역할·목표: 자기 기업의 담당자·조직·역할을 관리한다.
- 불편 가설: [assumption] 조직 변경과 권한 범위가 어긋날 수 있다.
- 사용 맥락: 고객 PC 우선·모바일 웹
- 권한 경계: 관리 권한만으로 전체 주문·지급·발급 결과를 조회하거나 실행하지 않음
- 근거: FR1.2, FR2 및 작성 계획 Q1.
- 기술 숙련도·사용 빈도: 미확인. 인터뷰·실사용 관찰 전 임의 수준을 부여하지 않는다.

### P3 내부 거래 운영 담당

- 역할·목표: 기업 이용 확인, 상품·계약 등록, 주문과 후속 요청 판단, HW 이행·회수 결과를 추적한다.
- 불편 가설: [assumption] 근거 미확인·부분 이행·외부 결과 충돌 때문에 판단이 지연될 수 있다.
- 사용 맥락: 사내망/승인 원격 접속 PC
- 권한 경계: 상품·기업·주문·계약·HW 업무 권한은 각각 필요하며 계약 자기 승인 금지
- 근거: FR1, FR4, FR6–FR7, FR9, FR15 및 작성 계획 Q1.
- 기술 숙련도·사용 빈도: 미확인. 인터뷰·실사용 관찰 전 임의 수준을 부여하지 않는다.

### P4 내부 대금 담당

- 역할·목표: 청구·지급·배분·연체·요금 조정·환불 결과를 연결한다.
- 불편 가설: [assumption] 미배분·중복·상충 근거로 지급 조건을 잘못 판단할 수 있다.
- 사용 맥락: 사내망/승인 원격 접속 PC
- 권한 경계: 대금 업무 권한만으로 계약·권한 기간을 직접 바꾸지 않음
- 근거: FR8, FR12, FR13.4 및 작성 계획 Q1.
- 기술 숙련도·사용 빈도: 미확인. 인터뷰·실사용 관찰 전 임의 수준을 부여하지 않는다.

### P5 내부 SW 권한 담당

- 역할·목표: 기업에 SW 권한을 발급하고 실제 기간 조정·갱신·회수 결과를 관리한다.
- 불편 가설: [assumption] 계약/실제 기간과 발급·갱신 결과가 혼동될 수 있다.
- 사용 맥락: 사내망/승인 원격 접속 PC
- 권한 경계: 기간 요청·승인은 각각 필요; 두 권한 보유 시 동일인도 별도 승인 가능
- 근거: FR10–FR11, FR3.3, FR13.4 및 작성 계획 Q1.
- 기술 숙련도·사용 빈도: 미확인. 인터뷰·실사용 관찰 전 임의 수준을 부여하지 않는다.

### P6 내부 계약 승인 담당

- 역할·목표: 등록자와 다른 사람으로서 합의 근거를 확인하고 계약 조건 적용을 승인한다.
- 불편 가설: [assumption] 근거와 승인 대상이 불일치하면 잘못된 조건이 적용될 수 있다.
- 사용 맥락: 사내망/승인 원격 접속 PC
- 권한 경계: 등록자 본인은 여러 역할·계정을 보유해도 해당 계약 조건 승인 불가
- 근거: FR3.2, FR7.3 및 작성 계획 Q1.
- 기술 숙련도·사용 빈도: 미확인. 인터뷰·실사용 관찰 전 임의 수준을 부여하지 않는다.

### P7 내부 권한 관리자

- 역할·목표: 내부 역할·권한을 관리하고 허용된 계정 복구를 수행한다.
- 불편 가설: [assumption] 권한 과다 부여나 복구 경로 악용이 발생할 수 있다.
- 사용 맥락: 사내망/승인 원격 접속 PC
- 권한 경계: 계정 복구 권한은 별도 확인; 모든 거래 업무 권한을 자동 보유하지 않음
- 근거: FR3.1, FR16.2 및 작성 계획 Q1.
- 기술 숙련도·사용 빈도: 미확인. 인터뷰·실사용 관찰 전 임의 수준을 부여하지 않는다.

### P8 기술 운영 담당

- 역할·목표: 배포·관측·복구·데이터 보존을 검증하고 1인 기술 운영 부담을 관리한다.
- 불편 가설: [assumption] 야간 실패·복구 근거 부족·수동 작업 누적이 생길 수 있다.
- 사용 맥락: 허용된 운영 접점; 직원 OMS 화면은 PC 조건 유지
- 권한 경계: 운영자 지위만으로 모든 고객 업무 데이터를 조회·정정하는 권한을 가정하지 않음
- 근거: NFR2–NFR11, NFR13–NFR14 및 작성 계획 Q1.
- 기술 숙련도·사용 빈도: 미확인. 인터뷰·실사용 관찰 전 임의 수준을 부여하지 않는다.

## 관계와 관점 우선순위

- 시나리오의 일차 가치 관점은 P1(고객 구매)과 P3(내부 거래 운영)이다. 나머지 관점은 기업 관리·승인·대금·권한 제공·운영이 완료되게 하는 필수 업무이며 우선순위가 낮아 제외된다는 뜻이 아니다.
- P2는 자기 기업의 사용자·역할을 관리하지만 P1의 조회·거래 권한을 자동 보유하지 않는다. P7의 내부 직원 권한 관리와도 구별한다.
- P3의 계약 등록과 P6의 해당 계약 승인은 서로 다른 사람이어야 한다. 한 사람이 다른 건에서 여러 업무를 맡을 수 있어도 본인 등록 승인 금지는 유지한다.
- P5의 실제 이용 기간 요청·승인은 각 권한과 별도 동작이 필요하며 동일인 수행을 허용한다. 이를 P3/P6 계약 승인에 적용하지 않는다.
- P4의 지급·배분 결과가 P3/P5의 제공 조건에 영향을 준다. 요청·승인·지급·실제 제공 완료는 별개로 추적한다.
- P8은 1인 기술 운영 검증의 주체다. P3/P6 등 실제 사업 업무 담당자가 확보됐다고 가정하지 않으며 운영자 권한을 모든 고객 데이터 접근 권한으로 자동 확대하지 않는다.

## Assumptions & Open Questions

- [assumption] 위 목표·불편 가설이 실사용자의 업무를 적절히 설명한다. 실제 고객·내부 업무 확인으로 검증한다.
- 실제 사업 운영 인력·지원 시간·관리자 확인 증거는 요구사항 OQ4·OQ10에서 해소한다. 8개 관점 동의는 8명 채용이나 특정 조직 구성 결정이 아니다.
- 상세 권한 목록·겸임 제약·접속 수단·복구 증거는 확정된 경계를 지키며 후속 설계에서 구체화한다.
