### 유지할 검증 원칙과 인계 사항

- US5.7·US6.6의 실패 원인 해소 후 재처리, 성공분 중복 방지, 미확인 재실행 방지는 상위 R-01의 후속 구체화로 충분히 타당하다. US5.1·US5.2는 R-02의 직원 등록·외부 연결 병행을 보존하며 모든 HW 업무에 양쪽 구현을 강제하지 않는다. 과거 검토 상태를 변경하지 않는다.
- 단위·통합 Standard와 test-after, 제품 코드 라인 커버리지 80% 하한을 유지한다. 테스트 수나 커버리지로 AC별 정상·실패·경계 증거를 대신하지 않는다. 이번 결과는 문서 검토이며 실행 시험은 하지 않았다.
- NFR6–NFR7·NFR12–NFR14처럼 상세 시험을 후속으로 보내는 요구는 traceability에서 해당 단계와 구체 책임을 명시해야 한다. 성능은 정상 부하·집중 후 회복·최초 실패 집계를, 보안·품질은 보고서 누락 보류를 보존한다. round 1에서는 추적 파일을 열람 대상으로 받지 않아 해당 파일의 행별 완전성을 검증하지 않았다. round 2에서는 허용된 traceability.json을 직접 확인했으며 결과를 아래에 기록했다.
- Given에 미정 규칙이 필요한 AC는 정책 해소 전 실행 준비 미완료로 유지한다. OQ1–OQ10 및 HB-01–HB-08은 실제 근거가 확보되기 전 해소로 표시하지 않는다. 위 보완은 기존 요구의 명시화로 판단하며 새로운 제품 선택 질문을 추가할 필요는 없다. 법정 보관 기간·외부 제공자·시간 제한·상태 전이의 구체 승자는 제안하지 않았다.
