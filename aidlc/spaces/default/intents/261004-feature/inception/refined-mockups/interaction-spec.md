# OMS 화면 상호작용 명세

## 목적과 연결

[화면 시안](mockups.md)의 24개 화면/증거 접점과 69 US·227 AC를 연결한다. PC 1280 이상·고객 모바일 유보·WCAG 2.2 AA는 Q1–Q5의 확인 답변을 따른다. 시각 시안은 계약 계산·서비스/API·외부 실행·상태 전이·보안 구현을 확정하지 않는다. 표의 업무 사실은 승인된 stories의 결과를 그대로 보존하며 화면 표시와 실제 검증 책임을 나눈다.

## 공통 진입·제출·재확인

- 진입: 신원/MFA → 고객 승인 기업·행위별 범위 또는 직원 PC/접속 환경 → 조회/실행 권한 → 허용 사실만 조회. 전체 불가에서는 본문을 렌더하지 않는다. 대금/발급 조회만 없으면 허용 주문 정보와 안전한 권한 안내를 제공한다.
- 읽기: 정상·확인된 0건·조회 중·조회 오류를 구별한다. 조회 실패는 마지막 확인 사실/확인 시각을 명시하거나 새 사실을 비워 두며 지급액 0·미지급·발급 실패로 대체하지 않는다.
- 쓰기: 입력 → 유효성·현재 권한/상태/근거 확인 → 대상/원래·변경 내용 검토 → 명시적 제출 → 요청 참조·접수 결과 → 실제 업무 결과. 수정 입력은 검토 단계로 돌아간다. 미정 값은 실행 전 관련 OQ 해소가 필요하다.
- 응답 미확인: 같은 요청 결과 재확인 → 원래 접수/실제 결과 대조. 클릭 방지만으로 효과 중복 방지를 증명하지 않는다. 확정 실패와 원인 해소·실패 잔량/조건 확인이 있어야 재처리한다.
- 충돌/오래된 근거: 원래 값/출처/내용 버전·변경 사실을 보여 주고 새 근거로 재검토한다. 최근 도착/최근 입력이라는 이유만으로 덮어쓰지 않는다. 의존한 출고·발급·환불 추가 실행만 보류한다.
- 복귀: 목록 필터·해당 기업 문맥·스크롤/행 초점은 동일 허용 세션에서 유지하는 설계 목표다. 작성 입력은 현재 작성 세션 내에서 유지하며 영구 초안 저장을 추가하지 않는다. 실제 세션 만료·중간 권한 회수·저장 범위는 OQ4 해소 후 상세 설계한다.

| 후속 요청 C06/S06 | 주문 전체·종류·사유 → 계약/실제 이행 → 판단 근거 | 요청/판단 → 보류/회수/환불의 개별 요청·결과·잔량 | 고객 부분 요청 금지, 내부 부분 결과 유지. 상충 사실에 의존한 추가 처리만 보류 |
| 계약 S08 | 고객 요청/합의 → 등록 내용/버전·등록자 → 다른 사람 승인 | 승인 대상·유효 시점·실제 적용 결과·원래/정정 이력 | 동일인(다른 계정도) 자기 승인 거절. 다른 승인자 없으면 미승인. OQ4/OQ10 |
| 고객 역할 C08 | 행위 각각 선택 → 각 부서/사업장 조합 → 최종 행위별 범위 | 해당 행위의 동일 범위 합집합과 부여/회수 이력 | 조회 전체+서울 IT 제출은 제출 전체로 확대 금지. 타 기업/직원 권한 생성 거절 |
| MFA/복구 A01/A03/S11 | 선택할 인증 수단·사전 복구 근거 또는 담당자 신원 확인 | 재등록·기존 수단 무효화·이력·알림 → 로그인 | 이메일만으로 MFA 해제 금지. 직원 망/PC 조건과 MFA 독립 |

## 컴포넌트 명세

형식은 component-spec-template의 Field·States·Props/Inputs·Responsive Behaviour·Accessibility·Usage Example을 따른다. 아래는 구현 중립적인 명세이며 컴포넌트 라이브러리 선정이 아니다. 모든 예시 prop은 설명용이다.

### CMP01 문맥·탐색

| Field | Value |
|---|---|
| Component | 문맥·탐색 |
| Description | 기업/사용자와 허용 업무를 확인하고 목록/상세를 이동 |
| Category | navigation |

**States**

| 상태 | 설명/트리거 |
|---|---|
| default / hover / focus | 초기 표시, 포인터 접근, 키보드/사용자 초점. 의미와 동작은 동일하고 초점은 눈에 보임 |
| disabled | 권한/조건 불충족 또는 처리 중. 이유를 별도 문구로 제공하고 민감 정보는 먼저 제거 |
| loading | 조회/처리 대기. 동일 실행 중복을 막고 요청 접수와 실제 결과를 구별 |
| error | 입력·조회·실제 처리 실패를 각각 구별. 수정/재조회/확정 실패 재처리 경로 연결 |
| empty | 조회 성공으로 해당 범위 0건이 확인된 경우만 |
| partial / unknown | 실제 성공 수량/금액·잔량 또는 결과 확인 필요, 같은 요청 재확인 |

**Props / Inputs**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| context | 해당 사실/문맥 객체 | yes | 없음 | context,allowedRoutes,currentRoute를 구별해서 전달. 미조회·미부여·미확인을 0/false로 강제 변환하지 않음 |
| authorizedActions / fields | 검증된 허용 행위·필드 집합 | yes | 허용 추정 없음 | 실제 서비스에서도 검증 필요, UI만으로 통제 아님 |
| operationState | 확인된 결과 또는 조회/처리 상태 | yes | 초기 조회 | 요청 참조·마지막 확인 사실·결과와 구별 |

**Responsive Behaviour**

| 범위 | 행동 |
|---|---|
| PC >=1280 CSS px | 1280/1440 좌측 탐색, 확대/좁은 PC에서는 문서 순서대로 위에 배치 |
| PC 창 축소·확대 | 내용·동작 유지, 단일 열/문서 순서/줄바꿈. 리플로우는 접근성 기준 별도 검증 |
| 고객 모바일 / 직원 모바일 | 고객 지원 여부 유보 / 직원 제공 제외. 창 크기로 단말 판정하지 않음 |

**Accessibility**

| 요구 | 명세 |
|---|---|
| 역할·이름·관계 | 본문 바로가기 → 탐색 링크 → h1 |
| 키보드·초점 | 화면 전환 시 h1로 이동, 뒤로 가면 원래 링크/목록 문맥. Tab/Shift+Tab, 링크 Enter, 버튼 Enter/Space, 대화상자 Escape; 드래그만으로 필수 행동을 요구하지 않음 |
| 상태·읽기 | 색상 외 텍스트. 오류와 상태를 적절히 알리고 필요 이상으로 전체 본문을 반복 발표하지 않음 |
| 대비·확대 | design-system-mapping의 대비 토큰, accessibility-checklist의 해당 A/AA 기준 적용. 수치 검증과 실제 흐름 확인은 구별 |

**Usage Example**

```text
CMP01: 허용 문맥 + context,allowedRoutes,currentRoute + 확인 상태 → 라벨/근거 표시 → 명시적 행동 → 접수/실제 결과
```

## 실제 구현으로 넘길 확인 사항

- 내부 직원의 허용 PC/접속 환경, 동일인 식별, 기업/행위별 데이터 범위, 연결 상세/API의 일관성은 보안/계약 설계와 실제 시험으로 확인한다.
- 지급·확보·출고·발급·회수·환불의 자동/직원/외부 경로는 각 계약·연동 근거로 연결한다. 미리보기의 합성 전환은 실제 자동화·외부 실행 성공을 입증하지 않는다.
- 수동 갱신은 FR11.1에 따라 실제 적용 기간·금액·회차·결과를 C05/S05에 표시한다. 자동 갱신 합의를 일회 수동 갱신의 필수 조건으로 추가하지 않는다.
- 중복·동시·역순·배포/복구 중 요청 시험은 NFR4/FR15.1과 관련 AC를 실제 통합 시험에 연결한다. disabled 버튼·같은 화면의 요청 캐시는 무결성의 증거가 아니다.
- US9.1–9.3·9.5–9.7은 새 OMS 업무 UI 없이 운영 접점 증거로 검증한다. 자동 복구 시도 시부터 업무 메신저+이메일 알림, 99.9% rolling 30일·30분 RTO·확정 접수 RPO0 목표의 구체 실패 범위, 정상 기술 운영 작업 시간 등의 상위 목표를 유지한다.

## 조회·제안 동의·조직/역할 편집 계약

### 보호된 사실의 동일 권한 투영

청구·지급/환불, 발급 결과, 주문 조회/실행 각각의 허용 필드를 구분해 CMP02·CMP03·CMP08·CMP15에 전달한다. 본문·목록·배지/색상·요약·필터·건수·알림·이력·연결 상세는 원래 사실보다 권한을 넓히지 않는다. 보호한 사실의 일부가 변경 시각·행위명·‘환불 확인 필요’ 등의 간접 표현에 남지 않아야 한다. 허용 주문 식별·판매 상태·허용된 HW 진행은 계속 표시한다.

시안의 주문 조회만 조건은 C01/C04/S07 및 연결 S03에서 대금·발급 상태를 표시하지 않는 합성 사례다. 직접 C05/S09 등에 진입하면 해당 업무 정보 없이 조회 권한 안내를 제공한다. 미부여 정보를 미지급·0원·실패로 변환하지 않는다. 실제 서비스는 필드/행위 권한과 기업·부서·사업장 범위를 모든 조회/API 경로에서 검증해야 한다. 클라이언트 정적 합성 자료의 감춤은 실제 통제 증거가 아니다.

| 부서 전체 | 부서 | 해당 부서의 모든 사업장 |
| 기업 전체 | 현재 자기 기업 문맥 | 자기 기업 전체; 타 기업 확대 없음 |

각 행위에 복수 범위를 추가/삭제한다. 미부여 행위에는 범위를 유효 권한으로 전달하지 않는다. 범위0인 허용 행위는 수정 안내를 제공한다. 역할 이름/행위별 범위 입력 → 최종15개 행위의 허용/미부여·범위 검토 → 정의 결과/이력을 표시한다. 저장만으로 사용자에게 자동 부여하지 않는다.

사용자 부여·회수는 담당자 선택 → 현재/제안 복수 역할 체크 → 부여/회수 차이·행위별 최종 합집합 검토 → 확인 결과/이력이다. 기업 전체 조회+서울·IT 제출+부산·IT 제출의 결과는 조회 기업 전체, 제출 두 조합이다. 서울·총무 제출이나 다른 행위의 기업 전체로 교차 확대하지 않는다. 다른 담당자의 역할·소속·활성 상태는 자동 변경하지 않는다. 실제 회수 효력·관리자 지정과 역할의 관계·동시 변경/조직 식별은 OQ4를 확정하고 검증한다.

컴포넌트 연결: CMP05 입력/오류·CMP06 전후/최종 범위 검토·CMP07 요청/미확인·CMP08 원래/정정 이력·CMP09 행위별 범위. 동적 범위 추가/삭제 후 호출 조작으로 초점을 복귀하고 필드의 라벨/관계를 유지한다. 담당자/역할/범위 값은 현재 작성 세션에서 유지하는 시안이며 영구 초안 저장을 추가하지 않는다.

## Assumptions & Open Questions

- [assumption] 컴포넌트 묶음과 독립 업무 구역이 실제 사용자에게 이해 가능하다. 인터뷰/사용성 시험은 아직 없음.
- 필수 입력 항목·배분/기간/후불 계산·상태 전이·의미상 중복 식별·외부 결과 대조·신원 확인은 OQ1–OQ4가 해소되기 전 실행 준비 완료로 판단하지 않는다.
- 자동/수동 경로의 상세 시점·승인 내용 변경·접속 중 권한 회수·재인증 후 입력 복귀·타임아웃은 관련 OQ에서 확정한다. 미리보기의 고정 합성 조건을 정책으로 채택하지 않는다.
- OQ5–OQ10의 잔여 항목과 Q5의 고객 모바일 지원 유보는 mockups의 최신 변경 영향 및 요구사항 원문을 따른다.
