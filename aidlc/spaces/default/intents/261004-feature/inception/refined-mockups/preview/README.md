# 클릭 가능한 OMS 화면 시안

## 열기

[index.html](index.html)을 로컬 브라우저에서 연다. 외부 리소스나 서버 호출 없이 같은 폴더의 styles.css·data.js·preview.js를 읽는다. 브라우저 자동화 도구가 file 접근을 제한하는 경우 이 폴더만 로컬 서버로 열 수 있다.

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory aidlc/spaces/default/intents/261004-feature/inception/refined-mockups/preview
```

접속: http://127.0.0.1:8765/index.html. 실행 위치는 저장소 루트다. 검토가 끝나면 서버를 중지한다. 외부 공개/배포는 하지 않는다.

## 검토 도구와 제품 UI

상단 회색 도구는 시안 검토용이다. 화면·7개 상태·업무 조건을 선택한다. 역할/상태 선택은 실제 인증이나 기업/행위 권한 통제가 아니다. 제품 UI는 아래 탐색·본문 구역이다. 모든 값은 합성 예시며 실제 주문·계정·키·외부 지급·권한 발급·계약 정보를 입력하지 않는다.

23개 화면과 주요 상호작용을 제공한다. 나머지 업무는 펼침 구역의 입력·검토·접수 표현과 69 US/227 AC를 연결한 상호작용 명세로 검토한다. 모든 AC의 실제 실행을 구현한 서비스가 아니다. 전체 정상 처리 결과를 모르는 업무는 기본적으로 접수/확인 안내를 사용한다. 복잡한 계약 계산·외부 이벤트·보안/운영 증거는 미구현이다.

작성 입력·예시 결과는 현재 브라우저 문서의 메모리만 사용한다. 새로고침하면 초기화된다. localStorage·영구 초안 저장·장바구니 보관·실제 로그인/메일 전송은 없다.

## 주요 확인 흐름

- 주문: 고객 상품 → 주문 작성. 상품 타입/수량 → 조건(일괄 기본, 부분 명시 선택) → 전체 검토 → 확인 대화상자 → 접수 결과. 전체 주문 조건 확인 예시는 상단 업무 조건에서 선택한다. 결과 미확인은 같은 요청 재확인으로 연결하고 같은 예시 참조를 유지한다.
- 계약: 직원 계약 등록·승인 → 다른 등록자의 계약 승인 펼침 → 내용 검토. 업무 조건을 계약 등록자 본인으로 두면 거절, 권한 확인 조건이면 다른 승인자의 결과 표시다.
- 배분: 직원 청구·지급·배분 → 미배분 지급 확인·정정 펼침. 초기 잔액600,000원.600,001은 거절,600,000은 예시 배분 반영. 주문 조회만 조건에서는 지급 정보를 표시하지 않는다.
- 기간: 직원 소프트웨어 제공 → 실제 이용 기간 조정 요청 → 별도 승인 → 기존 요청 결과 재확인. 두 권한 보유 합성 조건에서는 동일인도 별도 승인 가능하며 계약 자기 승인 금지 규칙과 구별된다.
- 수동 갱신: 고객 사용 권한·갱신 → 기간제 갱신 요청 → 내용 검토·제출. 직원 소프트웨어 제공 → 고객 요청 갱신 적용 결과 확인 → 정상 합성 결과 → 고객 사용 권한·갱신으로 돌아가 기간·금액·실제 결과 확인. 부분/미확인은 완료로 표시하지 않는다. 자동 갱신 합의는 일회 수동 갱신에 필수 조건이 아니다.
- 영구형: 고객 사용 권한·갱신의 이용형 선택에서 영구를 선택하면 기간제 갱신 입력을 제외한다.
- 권한/예외: 상단 화면 상태의 전체 접근 불가 또는 업무 조건의 주문 조회만·근거 미확인·상충 근거를 검토한다. 실제 서버/API가 해당 경계를 지키는지 증명하지 않는다.

## 검증 근거와 한계

가격 변경 동의는 고객 주문 상세·사용 권한/갱신의 전후 비교 패널에서 제안에 동의/거절한다. 상단 ‘제안 조건’으로 현재 내용·변경·조회 미확인을 검토한다. 대상·내용 버전·회차에 의사를 연결하고 새 내용은 새 검토를 요구한다.

고객 담당자·조직에서 초대와 기존 사용자의 부서/사업장·활성/관리자 변경을 검토한다. 마지막 관리자 회수는 관리자0명 경고와 다른 사용자 권한 유지 결과를 확인할 수 있다.

고객 역할·업무 범위에서15개 고객 행위와 조합/사업장 전체/부서 전체/기업 전체 범위를 선택한다. 새 역할 저장과 사용자 부여/회수는 별도 행동이다. 최종 합집합은 같은 행위의 범위만 합친다. 추가 코드 details.js는 이 합성 입력·검토 화면용이며 실제 권한 계산 API나 보안 구현이 아니다.

[접근성 체크리스트](../accessibility-checklist.md#미리보기-실행-근거)의 실제 Chromium 실행 근거를 따른다. [고객 PC](customer-1280.png), [직원 PC](staff-1280.png) 화면을 확인할 수 있다. 고객 모바일 지원 여부는 유보이며 320너비 검사는 PC 리플로우의 기초 검사다. 시안으로 실제 제품의 AA·정확성·가용성·국내 저장 적합성을 주장하지 않는다.
