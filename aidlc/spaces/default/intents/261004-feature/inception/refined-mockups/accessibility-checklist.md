# OMS 접근성 설계·검증 체크리스트

## 목표와 판정 범위

Q4에 따라 WCAG 2.2 AA를 전체 업무 흐름의 목표로 둔다. 적용 가능한 A·AA 성공 기준을 검사한다. 시안·고정 토큰·한 브라우저의 부분 동작으로 인증/실제 제품 AA 적합성을 선언하지 않는다. 본 문서의 대부분 항목은 실제 구현 검증 대기다. 미정·실패·미검증을 통과로 표시하지 않는다.

Q5 고객·직원 PC 1280 이상이 기본이다. 고객 모바일 지원은 유보지만 PC 확대·리플로우·키보드/보조기술 검증은 유지한다. 작은 뷰포트를 일괄 차단하는 구현은 이 목표에 맞지 않는다. 상위 모바일 문구 변경 대상은 NFR12·AC1.3.4·AC3.1.4이며 업무/권한 의미는 보존한다.

## 수치와 예외 검증

- 대비는 design-system-mapping의 계산 토큰을 출발점으로 실제 모든 화면·상태에서 검사한다. 텍스트 4.5:1, 적용 가능한 비텍스트 3:1의 정의/예외는 W3C 기준을 따른다.
- PC 1280·1440, 200% 텍스트 확대, 수직 콘텐츠 320 CSS px 상당 리플로우와 텍스트 간격 변경을 검사한다. 의미상 2차원 배치가 필요한 표 예외는 해당 부분만 근거로 판단하며 페이지 전체 예외로 확대하지 않는다.
- 제품 조작 높이40/36px 제안과 WCAG 2.2 AA 목표 크기24 CSS px 규칙을 구별한다. 간격·동등 조작·인라인 등 원문의 예외는 개별 검사하며 44px를 AA의 일괄 의무로 잘못 표기하지 않는다.
- 인증은 붙여넣기/비밀번호 관리 도구 등을 허용할 수 있는 수단을 실제 선정해 검증한다. 번호 입력 UI만 만들었다고 접근 가능한 인증을 증명하지 않는다.
